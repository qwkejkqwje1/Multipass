# Multipass — мультиаккаунты, куки и прокси для Chrome / Edge

Расширение (Manifest V3) для работы с множеством аккаунтов в одном браузере:

- **Мгновенное переключение аккаунтов** на любом сайте: куки (включая HttpOnly/Secure), `localStorage` и `sessionStorage`. Переключение занимает ~50 мс, вкладки сайта перезагружаются уже под новым аккаунтом.
- **Вход не слетает из-за временных куки**: сеансовые куки активного аккаунта закрепляются и переживают перезапуск браузера, а пропавшие — восстанавливаются из сохранённой сессии.
- **Менеджер прокси**: вставили список в любом формате — прокси проверены, видно страну, город, задержку и мёртвые. Привязка прокси к аккаунту или сайту, kill switch, авто-резерв, смена IP в один клик.
- **Синхронизация между браузерами** (Chrome ↔ Edge ↔ Яндекс ↔ другой ПК) со сквозным шифрованием: **папка на компьютере** (без интернета и серверов), GitHub Gist, WebDAV (Яндекс Диск, Nextcloud) или свой сервер из папки `sync-server`.
- **Перенос** аккаунтов и прокси зашифрованным файлом или текстовым кодом, импорт/экспорт куки (JSON, Netscape `cookies.txt`, Playwright).
- **Мастер-пароль**: сессии зашифрованы на диске, автоблокировка.

Работает в Chrome, Edge, Яндекс Браузере, Opera, Brave, Vivaldi — любом браузере на Chromium 116+.

### Что нового в 1.1
- **Временные (сеансовые) куки больше не роняют вход**: закрепление у активного аккаунта, возврат пропавших куки при запуске браузера, автосохранение не затирает сессию, если вход слетел. Настройки — в «Настройки → Временные куки», для отдельного сайта — в «Настройках сайта». Подробнее — [ниже](#временные-куки-чтобы-вход-не-слетал).
- **Синхронизация через папку в один клик**: «Выбрать папку…» в каждом браузере — и всё, парольная фраза не нужна (ключ лежит в папке, файл `multipass.key`). Фразу можно включить по желанию — для папки в облаке или на общем ПК. Обновите Multipass во всех браузерах, которые подключаете к папке. Уже подключённая с фразой папка продолжает работать как раньше.
- **Сначала сайты, внутри — аккаунты**: в окне текущий сайт сверху и развёрнут, остальные сайты сворачиваются; в панели управления карточки сайтов сворачиваются, есть «Развернуть все / Свернуть все».

## Установка

1. Распакуйте архив в постоянную папку (например, `Документы/multipass`). Не удаляйте её после установки — браузер грузит расширение прямо из неё.
2. Откройте страницу расширений:
   - Chrome / Brave / Vivaldi: `chrome://extensions`
   - Edge: `edge://extensions`
   - Яндекс Браузер: `browser://extensions`
   - Opera: `opera://extensions`
3. Включите **«Режим разработчика»** (переключатель справа вверху; в Edge — слева внизу).
4. Нажмите **«Загрузить распакованное»** и выберите папку **`extension`**.
5. Закрепите значок Multipass на панели (иконка пазла → булавка).

Обновление: замените файлы в папке и нажмите «Обновить» ⟳ на карточке расширения. Данные не теряются — ID расширения закреплён в `manifest.json` (поле `key`), поэтому его можно переносить в другую папку.

> Chrome при запуске может показывать предупреждение о расширениях в режиме разработчика — это нормально для расширений не из магазина.

## Быстрый старт (2 минуты)

1. Откройте сайт и войдите в первый аккаунт → значок Multipass → **«Сохранить вход»**, дайте имя.
2. **«Новый вход»** — Multipass запомнит текущий аккаунт и очистит сайт. Войдите во второй аккаунт и нажмите **«Сохранить»** у черновика.
3. Переключение — клик по аккаунту в окне (или `Alt+Shift+S` — следующий аккаунт на сайте).
4. Прокси: вкладка **«Прокси»** → вставьте список → «Добавить». Прокси проверятся автоматически.
5. Привяжите прокси к аккаунту (меню аккаунта → «Изменить» или в панели управления прямо в строке аккаунта). Пока аккаунт активен, его сайт идёт через его прокси.
6. Второй браузер на этом же ПК: **Панель управления → Синхронизация → «Папка на компьютере» → «Выбрать папку…»** — в обоих браузерах выберите одну и ту же папку. Больше ничего вводить не нужно.

Панель управления (кнопка с ползунками справа вверху окна или правый клик по значку → «Параметры») — там всё: массовые операции, маршрутизация, синхронизация, перенос, журнал, справка.

## Возможности

### Аккаунты
- В окне Multipass сначала идут **сайты, а внутри каждого — его аккаунты**: текущий сайт вверху и развёрнут, остальные сворачиваются (состояние запоминается), поиск ищет и по сайтам, и по аккаунтам. В панели управления карточки сайтов тоже сворачиваются: «Развернуть все» / «Свернуть все».
- Сайт = группа доменов (например, `google.com` + `youtube.com`), домены можно дописать вручную. Поддомены учитываются автоматически.
- Сохраняются куки всех доменов сайта + `localStorage`/`sessionStorage` открытых вкладок.
- Перед переключением текущая сессия автоматически сохраняется (настраивается) — свежие токены не теряются. Если вход на сайте уже слетел, автосохранение не затрёт хорошую сохранённую сессию.
- Временные (сеансовые) куки закрепляются, пока аккаунт активен, — см. раздел [«Временные куки»](#временные-куки-чтобы-вход-не-слетал).
- «Чистый вход» для нового аккаунта, черновики, «восстановить предыдущую сессию» (на случай ошибки).
- Цвет, теги, заметка, избранное, стартовая страница, поиск по всем сайтам.
- Видно, когда истекает вход, и в каком ещё браузере аккаунт сейчас активен (через синхронизацию).
- «Открыть» — сайт в новой вкладке сразу под нужным аккаунтом.
- Работает и в режиме инкогнито (отдельное хранилище куки), если разрешить расширению инкогнито.

### Прокси
- Форматы (можно вперемешку, по одному на строку):
  ```
  1.2.3.4:8080
  1.2.3.4:8080:user:pass
  user:pass@1.2.3.4:8080
  user:pass:1.2.3.4:8080
  http://user:pass@proxy.example.com:3128
  socks5://1.2.3.4:1080
  1.2.3.4 8080
  1.2.3.4:8080  # DE-Berlin        ← всё после # станет названием
  [2001:db8::1]:8080
  ```
  Тип определяется автоматически (HTTP / HTTPS / SOCKS5 / SOCKS4), дубликаты пропускаются, нераспознанные строки остаются в поле с пояснением.
- Проверка: реальный IP, страна, город, провайдер, часовой пояс, задержка; причина ошибки по-русски («неверный логин/пароль», «не отвечает»…). Фоновый мониторинг используемых прокси (каждые 2 мин) и полная перепроверка (раз в час).
- Группы прокси: назначьте аккаунту или сайту группу — будет выбран живой прокси из неё.
- **Kill switch** (включён по умолчанию): если прокси умер, запросы блокируются, а не уходят напрямую с вашим IP.
- **Авто-резерв**: для правил и режима «весь браузер» трафик переходит на живой прокси из той же группы. Для аккаунтов выключен по умолчанию, чтобы IP аккаунта не «прыгал» (включается в «Маршрутизации»).
- Защита от утечки IP через WebRTC при активном прокси.
- «Какой IP видит сайт» + предупреждение, если часовой пояс браузера не совпадает со страной прокси.
- «Сменить IP» (`Alt+Shift+P`) — следующий живой прокси.
- Экспорт списка в нужном формате, удаление мёртвых одной кнопкой.

### Маршрутизация
Режимы: **выкл** / **по правилам и аккаунтам** / **весь браузер через прокси или группу**.

Приоритет: исключения → прокси активного аккаунта сайта → правила для сайтов (сверху вниз) → «весь браузер» → напрямую.

Правила: `example.com`, `*.example.com` → прокси, группа, «напрямую» или «блокировать». Исключения (по умолчанию `localhost` и локальные сети 10.*, 192.168.*, 172.16–31.*) всегда идут напрямую. Есть тестер: вводите адрес — видите маршрут и IP, который увидит сайт.

## Синхронизация между браузерами

Синхронизируются сайты, аккаунты с сессиями, прокси (с логинами/паролями) и правила. Не синхронизируются настройки, мастер-пароль и статусы проверки (каждый браузер проверяет прокси сам). Данные шифруются **на устройстве** (AES-256-GCM): для папки — случайным ключом из файла `multipass.key` (или, по желанию, парольной фразой), для облачных вариантов — ключом из парольной фразы. Хранилище видит только зашифрованный блоб. Конфликты решаются по каждому элементу (новее — побеждает), удаления тоже синхронизируются. Синхронизация автоматическая: через несколько секунд после изменений, при открытии окна Multipass, при запуске браузера и по расписанию (для папки — каждую минуту, для облака — раз в 5 минут).

**Парольную фразу нигде не восстановить** — если используете её, запишите.

### Вариант 1. Папка на компьютере (один ПК, без интернета) — рекомендуется
Для нескольких браузеров на одном компьютере: Chrome, Edge, Яндекс, Opera, Vivaldi… В Brave доступ к папкам по умолчанию выключен: включите `brave://flags/#file-system-access-api` и перезапустите браузер (или используйте вариант с сервером).
1. Создайте пустую папку, например `Документы\Multipass`.
2. Браузер 1: Синхронизация → «Папка на компьютере» → **«Выбрать папку…»** → эта папка. Браузер спросит разрешение на папку — разрешите. Всё: Multipass создаст в папке ключ `multipass.key` и сразу выгрузит данные.
3. Браузер 2, 3…: то же самое, **та же папка**. Ключ подхватится сам — аккаунты, прокси и правила появятся через пару секунд.

**Про безопасность ключа.** Файлы в папке зашифрованы, но ключ `multipass.key` лежит рядом с ними: кто получит доступ к папке, тот сможет их расшифровать. Для папки на своём компьютере это нормально (сессии и так хранятся в профиле браузера на этом же диске). Если папка лежит в облаке (Яндекс Диск, Dropbox…) или компьютер общий — перед выбором папки отметьте **«Защитить парольной фразой»**: тогда ключ в папку не пишется, а фразу нужно один раз ввести в каждом браузере. Если в папке уже есть данные, защищённые фразой, Multipass сам попросит её ввести. Не удаляйте `multipass.key`, пока синхронизация подключена.

Как это работает: каждый браузер пишет в папку **свой** зашифрованный файл `multipass-<id>.json` и читает файлы остальных, поэтому конфликтов записи нет. Изменения уходят через ~2–3 секунды, а подтягиваются при открытии окна Multipass, при запуске браузера и раз в минуту.

- Папку можно положить внутрь **Яндекс Диска, OneDrive или Dropbox** — облачный клиент сам перенесёт файлы, и синхронизироваться будут разные компьютеры.
- Папку переименовали или перенесли — Multipass скажет «Папка не найдена» → «Выбрать папку…»; парольная фраза не нужна.
- Chrome/Edge иногда сбрасывают разрешение на папку после перезапуска. Тогда в окне Multipass появится «Нужен доступ к папке» → «Разрешить». В запросе браузера выберите **«Разрешать при каждом посещении»** — после этого спрашивать перестанет.
- «Отключить» убирает из папки файл этого браузера (и ключ, если это был последний браузер); данные в браузерах остаются.

### Вариант 2. GitHub Gist (между разными ПК)
1. Создайте токен: <https://github.com/settings/tokens> → «Generate new token (classic)» → отметьте только **`gist`**.
2. Браузер 1: Синхронизация → GitHub Gist → токен + парольная фраза → «Подключить». Будет создан секретный gist `multipass-vault.json`.
3. Браузер 2: тот же токен и та же фраза. ID gist вводить не нужно — хранилище найдётся само.

Секретный gist не виден в поиске, но доступен по ссылке — поэтому содержимое и зашифровано.

### Вариант 3. WebDAV (Яндекс Диск, Nextcloud, ownCloud…)
- **Яндекс Диск**: адрес `https://webdav.yandex.ru/multipass/vault.json`, логин — ваш логин Яндекса, пароль — **пароль приложения** (id.yandex.ru → Безопасность → Пароли приложений → «Файлы», WebDAV).
- **Nextcloud**: `https://ваш-сервер/remote.php/dav/files/ЛОГИН/multipass/vault.json`, пароль приложения из настроек безопасности.

Папка создаётся автоматически.

### Вариант 4. Свой сервер (папка `sync-server`)
Нужен Node.js 18+, зависимостей нет:
```bash
node server.mjs --token "длинный-случайный-токен-от-16-символов" --port 8787 --data ./data
# или: MULTIPASS_TOKENS=token1,token2 node server.mjs
```
- В локальной сети: адрес `http://192.168.1.10:8787`.
- Через интернет — только за HTTPS, например Caddy: 
  ```
  sync.example.com {
      reverse_proxy 127.0.0.1:8787
  }
  ```
- Docker:
  ```bash
  docker run -d --name multipass-sync --restart unless-stopped -p 8787:8787 \
    -v "$PWD":/app -v mpsync:/data -w /app node:20-alpine \
    node server.mjs --token "ваш-токен" --data /data
  ```
Сервер хранит только зашифрованные данные и 5 последних резервных копий. Несколько токенов = несколько независимых хранилищ (например, для разных людей).

### Несколько аккаунтов одного сайта одновременно
В одном профиле браузера куки сайта общие, поэтому одновременно активен **один аккаунт на сайт** (переключение — мгновенное). Чтобы держать открытыми несколько аккаунтов параллельно, используйте несколько профилей Chrome/Edge или разные браузеры: поставьте Multipass в каждый, подключите их к одной папке синхронизации — и в каждом окне выбирайте свой аккаунт. Значок «активен в…» подскажет, где аккаунт уже открыт.

## Временные куки: чтобы вход не слетал

Многие сайты ставят куки входа **без срока действия** — «до закрытия браузера» (сеансовые, или временные). Браузер стирает их при выходе, и получается: после перезапуска аккаунт разлогинен, а переключение на него «не держится». Что делает Multipass:

1. **Закрепление.** Пока аккаунт активен, временные куки его сайта превращаются в постоянные — на 30 дней (меняется в «Настройках», 1–399), срок продлевается каждые 12 часов. Новые временные куки, которые сайт ставит по ходу работы, закрепляются автоматически через пару секунд.
2. **В сохранённой сессии они остаются временными** — при переключении, экспорте и переносе срок не «прилипает», а при восстановлении куки снова закрепляются.
3. **Восстановление при запуске.** Если временные куки всё же пропали (закрепление было выключено, браузер закрыли раньше, чем куки закрепились), при старте браузера Multipass вернёт их из сохранённой сессии активного аккаунта и перезагрузит открытые вкладки сайта. Если хранилище заблокировано мастер-паролем — сразу после разблокировки.
4. **Защита сохранённой сессии.** Автосохранение не перезаписывает аккаунт, если из текущих куки пропала заметная часть временных/входных куки (то есть вход уже слетел) — в журнал пишется предупреждение, а рабочая сессия остаётся целой.

У аккаунта в окне значок часов с числом — сколько временных куки в его сессии. Жёлтый значок — закрепление выключено.

Настройки: **Настройки → «Временные куки»** (закрепление, срок, восстановление при запуске). Для отдельного сайта: **Аккаунты → ⋯ у сайта → «Настройки сайта» → «Закреплять временные куки»** (как в настройках / включено / выключено). Выключайте для сайтов, где важно, чтобы сеанс заканчивался с закрытием браузера (банки и т.п.).

Ограничение: если сайт сам завершает сеанс на сервере (например, через 12 часов бездействия), закрепление куки этого не отменит — придётся войти заново и нажать «Обновить».

## Перенос без синхронизации
Панель → **Перенос**:
- Экспорт всего или выбранных аккаунтов / только прокси и правил → файл `multipass-….json` или текстовый код `MPX1.…` (удобно переслать в мессенджере). С паролем — зашифровано, без пароля — нет (будет предупреждение).
- Импорт: файл или вставленный код.
- Импорт куки из других расширений (EditThisCookie, Cookie-Editor — JSON) и `cookies.txt` (Netscape) как нового аккаунта.
- Экспорт куки аккаунта: JSON, Netscape, Playwright `storageState`.

## Горячие клавиши
| Клавиши | Действие |
|---|---|
| `Alt+Shift+M` | Открыть Multipass |
| `Alt+Shift+S` | Следующий аккаунт на текущем сайте |
| `Alt+Shift+P` | Сменить IP — следующий живой прокси |
| `Alt+Shift+X` | Прокси: включить / выключить |
| — | «Чистый вход» (назначается вручную) |

Изменить: `chrome://extensions/shortcuts` (в Edge — `edge://extensions/shortcuts`). Также есть пункты в контекстном меню страницы и значка.

## Безопасность и приватность
- Все данные — локально в профиле браузера. Никакой телеметрии, никаких сторонних серверов.
- Сетевые запросы расширения: проверка прокси (по умолчанию `ip-api.com`, адрес меняется в Настройках) и выбранная вами синхронизация.
- **Мастер-пароль** (Безопасность): сессии на диске шифруются AES-256-GCM, ключ из пароля через PBKDF2-SHA256 (310 000 итераций); автоблокировка через 30 минут бездействия (настраивается), блокировка вручную — кнопкой в окне.
- Синхронизация шифруется на устройстве: через папку — случайным ключом из `multipass.key` (или парольной фразой, если включить защиту), через облако — парольной фразой. Файлы переноса — своим паролем.
- Закреплённые временные куки хранятся в профиле браузера как обычные постоянные куки — на общем компьютере выключите закрепление (или используйте мастер-пароль и выходите из аккаунтов).
- Не пересылайте никому незашифрованный экспорт: куки = доступ к аккаунту.

## Ограничения (честно)
- **Прокси на отдельную вкладку невозможен** — Chrome выбирает прокси только по адресу запроса. Поэтому маршрут задаётся сайту или аккаунту.
- **SOCKS5 с логином/паролем Chrome не поддерживает** (только HTTP/HTTPS-прокси с авторизацией). Берите HTTP-доступ у того же провайдера или авторизацию по IP.
- **IndexedDB и Service Worker-кэш не переносятся.** Сайты, хранящие вход только там (WhatsApp Web, Telegram Web), могут попросить войти заново.
- Синхронизация через папку работает только в браузерах на Chromium (File System Access API). Браузер может изредка просить подтвердить доступ к папке — это одна кнопка.
- Если другое расширение управляет прокси (VPN-расширения), они будут конфликтовать — включённым должно быть одно.
- Многие сайты привязывают сессию к IP или отпечатку браузера: перенесённая на другой ПК сессия может потребовать подтверждения входа. Сохраняйте аккаунту его прокси.
- **Отпечаток браузера не подделывается** (Canvas, WebGL, шрифты и т.п.). Грубая подмена из расширения сама по себе выдаёт бота. Если нужна полноценная антидетект-изоляция — это задача антидетект-браузеров, а Multipass закрывает куки, IP, WebRTC и предупреждает о несовпадении часового пояса.
- Для публикации в Chrome Web Store удалите поле `key` из `manifest.json`.

## Структура
```
extension/            ← папка для «Загрузить распакованное»
  manifest.json
  background.js       service worker
  src/bg/             аккаунты, сессии, прокси, маршрутизация, синхронизация, перенос, хранилище
  src/shared/         разбор прокси, форматы куки, шифрование, домены
  ui/                 окно (popup) и панель управления (dashboard)
sync-server/server.mjs  сервер синхронизации (Node 18+, без зависимостей)
```
